# جيم — دليل التنفيذ (لـ Claude Code)

نموذج أولي HTML/CSS/JS ثابت لصفحتين من منصة «جيم» (اسمها السابق «غرفة القيادة»). الهدف إنه يتحول لـ **ASP.NET Core Razor Views + Vanilla JS**، من غير React، مع الحفاظ على الشكل والسلوك بالظبط.

## الصفحات (12 صفحة + فهرس)

افتح `index.html` للتنقل بين كل الصفحات.

| المستوى | الملف | الوصف |
|---|---|---|
| عام | `login.html` | الدخول برمز المنظمة + البريد + كلمة المرور، أو SSO |
| المنصّة | `platform-organizations.html` | قائمة المنظمات وحالة التجهيز (جاهزة، قيد التجهيز، فشل، معطّلة) + نافذة «منظمة جديدة» |
| المنصّة | `platform-organization-details.html` | مراحل التجهيز وسجلّه، بيانات المنظمة، والإجراءات (تبويبات) |
| المنصّة | `platform-templates.html` | مكتبة النماذج: عناصر المحادثة، نماذج اللوحات، مكتبة المؤشرات، والقواعد العامة، مع وصف الذكاء الاصطناعي لكل نموذج وتعديله وإضافة نماذج جديدة |
| عام | `dashboard-gallery.html` | مكتبة لوحات المتابعة: 212 لوحة بكل صفحاتها وفلاترها، مع بحث وتصنيفات |
| المنظمة | `org-projects.html` | قائمة المشاريع + إنشاء مشروع فوري |
| المنظمة | `org-users.html` | حسابات المنظمة وربطها بالمشاريع + نافذة الدعوة |
| المنظمة | `org-settings.html` | الملف التعريفي، الخطة، الأمان (SSO وMFA)، هوية اللوحات المنشورة، نموذج الـ AI |
| المشروع | `project-workspace.html` | المحادثة واللوحات |
| المشروع | `project-sources.html` | الـ Connector المباشر + مصادر API والملفات + نافذة «إضافة مصدر» |
| المشروع | `project-permissions.html` | الأعضاء وأدوارهم، مصفوفة الأدوار، وصلاحيات على مستوى البيانات (Row-level) |

- صفحات المنصّة ليها قائمة جانبية مختلفة (`platform_sidebar`): من غير اختيار منظمة ومن غير مشاريع، لأن الـ Super Admin مش بيشوف بيانات المنظمات.
- النوافذ المنبثقة كلها `<dialog class="modal">`، وبتتفتح بأي زر عليه `data-open="id"`.

### وضع المعاينة: زر «عرض كـ»

في أسفل القائمة الجانبية (وفي صفحة الدخول زر عائم) فيه زر بيبدّل بين 5 شخصيات تجريبية عشان تشوف الفرق:

1. أحمد: مسؤول المنصّة.
2. محمد: مسؤول المنظمة.
3. سارة: مالكة «المبيعات» ومحررة «الموارد البشرية».
4. نورة: محررة.
5. خالد: مشاهد في «المبيعات» فقط.

ممكن كمان تفتح أي صفحة بـ `?as=super|orgadmin|owner|editor|viewer`.

**طريقة العمل (`assets/js/roles.js`)** — دي محاكاة في الواجهة بس:

- `<body data-scope="platform|org|org-admin|project">`: لو الدور مالوش وصول، بيتحوّل لصفحته الرئيسية.
- `data-require="super|org-admin|project:viewer|project:editor|project:owner"`: العنصر بيختفي لو الدور أقل.
- `data-require-enable="..."`: العنصر بيتعطّل بدل ما يختفي (مثال: قوائم تغيير الدور).
- `data-show-roles="viewer"`: يظهر لأدوار معيّنة بس (مثال: تنبيه «أنت مشاهد»).
- `data-project="sales|hr|proc|cx"`: أي عنصر مرتبط بمشروع (في القائمة، أو الكروت، أو النشاطات) بيختفي لو المستخدم مش عضو فيه.

> **مهم للتنفيذ:**
> - في التطبيق الحقيقي `roles.js` وزر «عرض كـ» **يتشالوا**.
> - نفس القواعد دي تتطبّق على **السيرفر**: Authorization Policies على الـ Controllers، وفلترة المشاريع بالـ ProjectMembers في كل Query.
> - في الـ Razor Views نفس السمات تتحوّل لشروط `@if (User.Can(...))`.
> - إخفاء عنصر في الواجهة مش حماية لوحده.

## التحويل لـ Razor

1. **`_Layout.cshtml`**: الـ `<head>` و `icons.js` و `.app` و `.scrim` و `app.js`. الصفحات تضيف سكريبتاتها في `@section Scripts` (صفحة المشروع بس هي اللي محتاجة ApexCharts و `charts.js`).
2. **`_Sidebar.cshtml` (Partial)**: الـ `<aside class="sidebar">` موجود بنفس الشكل في الصفحتين. وتتولد قيمه من الجلسة:
   - المنظمة الحالية (الاسم، الخطة، عدد المشاريع) من الـ Tenant الحالي.
   - قائمة «المشاريع» = المشاريع اللي المستخدم ليه صلاحية عليها **فقط** (ProjectMembers).
   - العنصر النشط: الكلاس `is-active` و `aria-current="page"`، والمشروع الحالي ياخد `is-open`.
   - قسم «المنظمة» (المستخدمون، الإعدادات) يظهر لـ **Org Admin بس**.
3. **`_Topbar`**: مسار التنقل (منظمة / مشروع / صفحة) والأزرار حسب الصفحة.
4. القيم كلها تيجي من `tokens.css`، وممنوع تكتب ألوان أو مقاسات ثابتة في الـ Views.

## مساحة المشروع: ربط اللوحة بالـ AI

كل عنصر في اللوحة `<article class="widget">` لازم يطابق عنصر في JSON اللوحة اللي الـ AI بيرجّعه. الأنواع المستخدمة هنا:

| النوع في JSON | المكون في الواجهة | العرض في الشبكة |
|---|---|---|
| `kpi` | `.widget.kpi` + sparkline (`#sp-*`) | `span-3` |
| `kpi_progress` | `.widget.kpi` + `.bar-track` | `span-3` |
| `line` / `area` | `#ch-trend` (ApexCharts area) | `span-8` |
| `donut` | `#ch-sector` + `.donut-list` | `span-4` |
| `bar_h` | `.hbars` (HTML/CSS، مش ApexCharts، عشان الاتجاه من اليمين للشمال) | `span-5` |
| `table` | `.table` | `span-7` |
| `summary` | `.insight` (الخلاصة) | عرض كامل |

- **`source`**: كل عنصر ليه نافذة `.w-src` بتفتح من زر ⓘ، وفيها المصدر وطريقة الحساب. دي بتتملي من حقل `source` في JSON.
- **`narration`**: زر «استمع للملخص» (`.narrate`) بياخد النص من `data-text`. الموجود حاليًا Web Speech API كتجربة فقط، وفي الإنتاج يتحول لـ Azure Speech.
- **ألوان الرسوم** ثابتة بالترتيب `--chart-1..4`، ومتحقق منها لعمى الألوان. ممنوع تولّد ألوان جديدة. العنصر الخامس وما بعده يتجمع تحت «أخرى».
- **ألوان الحالات** (`--ok` / `--warn` / `--danger`) محجوزة للنمو والانخفاض والتنبيهات، ومتستخدمش كألوان سلاسل بيانات.

## المحادثة (عمود جانبي على الشمال)

المحادثة عمود ثابت على الشمال بجانب اللوحة (`.dock` داخل `.workspace`، عرضه `--chat-w`). وليها حالتين في `data-state`:

| الحالة | الشكل | الزر |
|---|---|---|
| `open` | عمود المحادثة ظاهر، واللوحة بجانبه | — |
| `hidden` | العمود بيختفي واللوحة تاخد العرض كله، ويظهر زر عائم «اسأل جيم» في الركن وزر محادثة في الشريط العلوي | زر الإخفاء في رأس المحادثة `[data-chat="hidden"]`، والفتح بـ `[data-chat="open"]` |

**سلوك العمود:**

- الحالة بتتحفظ لكل مستخدم في `localStorage` (`jeem.chat`).
- على الشاشات الأصغر من 1080px المحادثة بتبدأ مخفية، ولما تتفتح بتطلع كدرج منزلق فوق اللوحة.
- زر `/` من الكيبورد بيفتح المحادثة ويركّز على الكتابة.
- الرسوم البيانية بتتعاد رسمها تلقائي لما العرض يتغيّر.

**أوضاع المحادثة: بناء اللوحة / استفسارات / النماذج** (`.chat-modes`، والحالة في `.chat[data-mode]`)

| | بناء اللوحة (`build`) | استفسارات (`ask`) |
|---|---|---|
| الهدف | بناء اللوحة الحالية أو تعديلها | سؤال سريع عن البيانات |
| تأثيره على اللوحة | بيعدّل JSON اللوحة | **مالوش أي تأثير على اللوحة** |
| شكل الرد | خطوات التنفيذ + ملخص + كارت اللوحة | رقم (`.answer-card`) أو قائمة (`.answer-list`) أو جملة، ومعاها المصدر |
| الصلاحية | مالك ومحرر | كل الأدوار، ومنها المشاهد |

**تفاصيل:**

- كل نوع له محادثة مستقلة: `#thread-build` و`#thread-ask`.
- الـ placeholder بيتغيّر حسب النوع، و«لوحة جديدة» بتظهر في وضع البناء بس.
- لون التمييز: أزرق للبناء، وفيروزي للاستفسارات.
- زر **«أضف للوحة»** على أي إجابة استفسار بيحوّلها لعنصر في اللوحة (للمحرر والمالك).
- **المشاهد:** تبويب البناء معطّل عنده، فبيفتح على الاستفسارات تلقائي.
- آخر نوع اختاره المستخدم بيتحفظ في `localStorage` (`jeem.chatMode`).
- في الـ API: ابعت `mode` مع كل طلب. وضع `ask` لازم يرجّع إجابة نصية/رقمية بس، من غير `widgets`.

**تبويب «النماذج»** (`#thread-templates`، ويرسمه `assets/js/templates.js`)

- **المحتوى:** معرض عناصر جاهزة (مؤشر، مقارنة سنوية، خط زمني، تحقيق المستهدف، توزيع، مراحل صفقات، أوقات الذروة، جدول). وفيه بحث وتصنيف: مؤشرات / رسوم بيانية / جداول.
- **الضغط على نموذج:** بيضيفه **للوحة الحالية** فورًا. العنصر بيظهر في آخر الشبكة بإطار مميز، والصفحة بتنزل عليه، ويظهر إشعار «تمت الإضافة». والعنصر المضاف ليه زر حذف.
- **الصلاحية:** المالك والمحرر بس. المشاهد التبويب معطّل عنده.
- **أثناء النماذج:** خانة الكتابة بتختفي، لأن التبويب ده مش محادثة.
- **في الـ API:**
  - القائمة: `GET /projects/{id}/widget-templates`، وبترجع النماذج المتاحة حسب مصادر المشروع (النموذج اللي مصدره مش متصل مايظهرش).
  - الإضافة: `POST /dashboards/{id}/widgets { templateId }`، وبترجع الـ widget ببيانات حقيقية بنفس صيغة JSON اللوحة.

### مكتبة المؤشرات داخل «النماذج» (`assets/js/kpi-library.js` + `templates.js`)
- في أعلى تبويب «النماذج» زرّان للتبديل: **عناصر جاهزة** (النماذج الثمانية) و**مكتبة المؤشرات** (1,899 مؤشرًا من Spider Strategies: 6 أقسام وظيفية و20 قطاعًا).
- `kpi-library.js` ملف بيانات مولّد آليًا: `window.JEEM_KPI_LIBRARY = {mtypes, cats:[ar,en,0|1,url], subs, rows:[catIdx, subIdx, ar, en, mtIdx]}`. يُحمَّل قبل `templates.js`.
- الفلترة:
  - بحث بالعربي والإنجليزي، مع توحيد أشكال الألف والتاء المربوطة والياء.
  - قائمة تصنيفات مقسومة إلى «الأقسام الوظيفية» و«القطاعات».
  - شرائح لنوع القياس: نسبة، زمن / مدة، قيمة مالية، درجة / مؤشر رأي، عدد، أخرى.
- العرض تدريجي، 40 مؤشرًا في كل دفعة، مع زر «عرض المزيد».
- الضغط على مؤشر يضيف عنصرًا `span-4` للوحة، وشكله يتحدد حسب نوع القياس:
  - **نسبة:** قيمة مع شريط تقدم وعلامة للمستهدف.
  - **زمن:** قيمة مع اتجاه (الأقل أفضل).
  - **مالية:** قيمة مع اتجاه وخط صغير.
  - **درجة:** قيمة من 5.
  - **عدد:** أعمدة 6 أشهر.
- القيم تجريبية، لكنها ثابتة لكل مؤشر لأنها مولّدة من الاسم. يظهر تحت العنصر سطر «قيم تجريبية — اربطه بمصدر».
- **في التطبيق الفعلي:**
  - جدول `KpiDefinitions (Id, NameAr, NameEn, CategoryId, SubGroup, MeasureType, Unit, Direction, DefaultVisual, Formula, SourceUrl)` على مستوى المنصة، مشترك بين كل المؤسسات. يُضاف له لاحقًا التعريف والمعادلة.
  - `GET /kpi-library?q=&category=&measureType=&page=` للبحث بصفحات من السيرفر بدل تحميل الملف كله.
  - `POST /dashboards/{id}/widgets {kpiDefinitionId}`: ينشئ العنصر بحالة «غير مربوط». بعدها يطلب جيم من المستخدم في المحادثة اختيار المصدر والعمود، أو يقترحهما تلقائيًا من مصادر المشروع.
  - نوع القياس هنا تصنيف تقريبي من الاسم الإنجليزي، فيُراجع يدويًا قبل الإطلاق.
  - إظهار اسم المصدر Spider Strategies ورابطه واجب (موجود أسفل القائمة).

### معرض «لوحة جديدة» (`assets/js/dashboards.js`)

زي شاشة البداية في PowerPoint. بيتفتح من زر **«لوحة جديدة»** في الشريط العلوي أو في رأس المحادثة (`[data-open-gallery]`)، ومتاح للمالك والمحرر.

**محتوى المعرض:**

- **بدايات سريعة:**
  - «لوحة فارغة»: بتفضّي اللوحة وتفتح تبويب «النماذج».
  - «اطلب من جيم»: بتفتح «بناء اللوحة» وتكتب بداية الطلب.
- **8 نماذج لوحات كاملة**، في كل نموذج **10 عناصر** (4 مؤشرات + 6 رسوم):

  | النموذج | التصنيف |
  |---|---|
  | أداء المبيعات التنفيذي | المبيعات والتسويق |
  | التسويق والحملات | المبيعات والتسويق |
  | متابعة المشاريع والمبادرات | المشاريع |
  | المالية والميزانية | المالية |
  | الموارد البشرية والقوى العاملة | الموارد البشرية |
  | المشتريات والموردين | المشتريات |
  | تجربة العملاء والشكاوى | تجربة العملاء |
  | العمليات والتشغيل | العمليات |

- **تصفية وبحث:** تصنيفات على الجنب، وبحث بالاسم أو المصدر.
- **كارت كل نموذج:** مصغّرة حقيقية لتوزيع العناصر العشرة، ومصادره، وشارة «الأكثر استخدامًا».

**طريقة الاستخدام:**

1. الضغط على نموذج بيفتح **معاينة**: مصغّرة كبيرة، وقائمة العناصر العشرة، والمصادر المطلوبة.
2. **«استخدم هذا النموذج»** بيستبدل محتوى اللوحة بالعناصر العشرة، ويغيّر العنوان والملخص.

**طريقة العمل:**

- كل نموذج = بيانات (`widgets[]` بنفس أنواع JSON اللوحة: `kpi`، `line`، `donut`، `hbars`، `cbars`، `table`، `funnel`، `heat`).
- `layout` بيحدد ترتيب ومساحات الرسوم، فكل نموذج شكله مختلف.

**في الـ API:**

- `GET /dashboard-templates`: بيرجّع النماذج. الأفضل يتعلّم النموذج اللي مصادره مش متصلة بالمشروع، أو يتطلب ربط مصدر قبل الاستخدام.
- `POST /projects/{id}/dashboards { templateId }`: بينشئ **لوحة جديدة** في سجل اللوحات ببيانات حقيقية، ومش بيمسح اللوحة القديمة.

**باقي سلوك المحادثة:**

- `#ask` (form): الإرسال حاليًا **تجريبي** في `app.js` (`setTimeout`)، ومحتاج يتبدّل باستدعاء الـ API الحقيقي (SSE أو streaming لو متاح).
- **خطوات التنفيذ** (`.steps`): بتتعرض وهي بتحصل. الخطوة الجارية تاخد `.st.run` مع `.jbars.is-live`.
- **أزرار المصادر** (`.src-toggle[aria-pressed]`): موجودة فوق خانة الكتابة، وبتحدد المصادر المسموح بيها في السؤال (strict source gating)، ولازم تتبعت مع كل طلب.
- **الأسئلة المقترحة** (`.followups .chip`): بتملى صندوق الكتابة، وبتيجي من رد الـ AI.
- أي سؤال متابعة **بيعدّل اللوحة الحالية**. وزر «لوحة جديدة» هو اللي بيبدأ لوحة من الصفر.

## مكتبة النماذج — مسؤول المنصّة (`platform-templates.html`)
صفحة واحدة يدير منها Super Admin كل النماذج التي يراها المستخدمون، ومعها **وصف الذكاء الاصطناعي** (الـ prompt المرسل لجيم عند اختيار النموذج). تظهر في قائمة المنصّة باسم «مكتبة النماذج». الصفحة على مستوى المنصّة، لذلك `data-scope="platform"` وتُحوَّل باقي الأدوار عنها.

**مصدر البيانات الموحّد: `assets/js/catalog.js` (`window.JEEM_CATALOG`)**
- نقلت إليه بيانات النماذج من `templates.js` و`dashboards.js`، فصارت الصفحات الثلاث تقرأ من مصدر واحد: المحادثة، ومعرض «لوحة جديدة»، ومكتبة النماذج.
- يُحمَّل بعد `kpi-library.js` وقبل `templates.js` و`dashboards.js` و`platform-templates.js`.
- التعديلات تُحفظ محليًا في `localStorage` (`jeem.catalog.v1`) لمحاكاة الـ API. فلو عدّلت نموذجًا في المكتبة، يظهر التعديل في المحادثة والمعرض فورًا.
- لا يظهر للمستخدم إلا ما حالته `published`. المسودة والموقوف يظهران في المكتبة فقط.

**التبويبات الأربعة**

- أزرار المتغيرات تُدرج `{{...}}` في مكان المؤشر. المتغير غير المعروف يُعلَّم بالأحمر ويمنع الحفظ.
- الإجراءات المتاحة:
  - «نسخ كنموذج جديد»: النسخة تبدأ كمسودة.
  - «إيقاف/نشر» من الجدول مباشرة.
  - «استعادة الأصل» للنماذج الأساسية المعدّلة.
  - «حذف» للنماذج المضافة فقط، ويحتاج تأكيدًا بضغطة ثانية.
  - «ابدأ من» عند إنشاء نموذج لوحة: هيكل فارغ أو نسخة من نموذج موجود.

- `{{kpi_name}}`، `{{kpi_name_en}}`، `{{category}}`، `{{measure_type}}`: للمؤشرات فقط.


**إيقاف وإظهار تصنيف كامل (مكتبة المؤشرات)**
- تبويب «مكتبة المؤشرات» فيه طريقتين للعرض:
  - **حسب التصنيف** (الافتراضي): 26 كارت مقسومين على مجموعتين، الأقسام الوظيفية (6) والقطاعات (20). كل كارت فيه مفتاح تشغيل، وعدد المؤشرات الظاهرة من الإجمالي، والموقوف فرديًا، وعدد المؤشرات بوصف مخصص، وزر «عرض المؤشرات». ولكل مجموعة زرين «إظهار الكل» و«إيقاف الكل».
  - **كل المؤشرات**: الجدول بالمؤشرات واحد واحد. لو اخترت تصنيف من الفلتر يظهر فوق الجدول شريط فيه مفتاح نفس التصنيف.
- **قاعدة الحالة:** الحالة الفعلية للمؤشر = موقوف لو تصنيفه موقوف، وغير كده حالته هو. إيقاف التصنيف **مابيغيرش** حالة المؤشرات نفسها، فلما يرجع يظهر كل مؤشر بيرجع لحالته اللي كان عليها.
- المؤشرات اللي تحت تصنيف موقوف بتظهر في الجدول «موقوف مع التصنيف»، وزر إيقافها الفردي بيبقى مقفول لحد ما التصنيف يرجع يظهر.
- بعد أي إيقاف أو إظهار بتطلع رسالة فيها زر «تراجع» لمدة 6 ثوانٍ.
- في المحادثة: التصنيف الموقوف بيختفي من قائمة التصنيفات، ومؤشراته مابتظهرش في البحث، والعدد في التبويب بيتحدّث.
- **API مقترح:** جدول `KpiCategories (Id, NameAr, NameEn, Type, IsEnabled)`، و`PUT /platform/kpi-categories/{id} {isEnabled}`، و`PUT /platform/kpi-categories/bulk {ids[], isEnabled}`. الاستعلام اللي بيرجّع المؤشرات للمستخدم يكون `WHERE k.Status='published' AND c.IsEnabled=1`.

**الـ API المقترح**
- `GET/POST /platform/widget-templates`، `PUT/DELETE /platform/widget-templates/{id}`
- `GET/POST /platform/dashboard-templates`، `PUT/DELETE /platform/dashboard-templates/{id}` (العناصر العشرة كـ JSON أو جدول فرعي `DashboardTemplateWidgets`)
- `GET /platform/kpi-library?q=&category=&measureType=&status=&page=`، `PUT /platform/kpi-library/{id}`، `POST /platform/kpi-library`
- `GET/PUT /platform/ai-settings`: القواعد العامة والقالب العام للمؤشرات.
- **نقطة مهمة:** بناء الـ prompt النهائي يتم في السيرفر. الترتيب: القواعد العامة، ثم وصف النموذج، ثم تعويض المتغيرات من بيانات المشروع. المتصفح لا يرسل الـ prompt أبدًا، بل يرسل `templateId` فقط. بهذا لا يقدر المستخدم يعدّل الوصف.
- احفظ كل إصدار في جدول `TemplateVersions (TemplateId, Version, Snapshot, ChangedBy, ChangedAt)` لتسهيل المراجعة والاسترجاع.
- حقل «متاح لخطط» يفلتر النماذج حسب خطة المنظمة عند `GET` من داخل المشروع.

## لوحة تفاعلية: شبكة الأنظمة واللوائح (`policy-network.html`)
لوحة تعرض كل نظام كشبكة علاقات بدل المستند. حول كل نظام تظهر لوائحه، والجهات المُلزمة به، والمنصات التي يُنفَّذ عبرها، والشكاوى التي تنشأ عنه. مكتوبة بـ Vanilla JS + SVG بلا مكتبات خارجية، وفيها محاكاة قوى (force-directed) مكتوبة يدويًا.

**التفاعلات**
- **ضغطة على عقدة:**
  - الكاميرا تنتقل لجوارها.
  - الجيران يتنوّرون والباقي يبهت، والخطوط المرتبطة تتحرك.
  - تظهر أسماء العلاقات على الخطوط.
  - تتحدث المؤشرات العلوية واللوحة الجانبية والرسوم الأربعة أسفل الشبكة على نطاق العقدة (Cross-filtering).
- **تمرير الماوس:** على العقدة يظهر الاسم والقيم، وعلى الخط يظهر نوع العلاقة.
- **الحركة في الشبكة:** سحب العقدة يحرّكها والشبكة تتكيف معها، وسحب الخلفية للتحريك، وعجلة الماوس للتكبير حول المؤشر، وأزرار التكبير والملاءمة.
- **تصفية الأنواع:** إخفاء أي نوع أو إظهاره، والشبكة تعيد ترتيب نفسها.
- **الشريط الزمني:** من 2019 إلى 2026، مع زر تشغيل يعرض كيف نشأت الشبكة سنة بسنة.
- **اختيار النظام:** أزرار أعلى الصفحة تركّز على نظام واحد.
- **البحث بالاسم:** يطبّع الهمزات والتاء المربوطة.
- **«اسأل جيم»:** السؤال يُنوّر العقد ذات الصلة ويضبط الكاميرا عليها، ويكتب الإجابة حرفًا بحرف.
- **عرض كجدول:** بديل للرسم لقارئات الشاشة والطباعة. العقد قابلة للتنقل بلوحة المفاتيح (Tab ثم Enter)، وEsc يلغي التحديد.
- **الترميز:** كل نوع له لون **وشكل** معًا (دائرة، مربع، معيّن، سداسي) حتى لا يعتمد التمييز على اللون وحده. الألوان اجتازت فحص عمى الألوان.
- **احترام إعداد تقليل الحركة** (`prefers-reduced-motion`).

**الملفات**
- `assets/js/policy-graph-data.js`: بيانات تجريبية بصيغة `nodes`/`edges`.
- `assets/js/policy-graph.js`: المنطق كاملًا.
- قسم `.pg-*` في `app.css`.

**الربط مع الخادم**

جدولان في SQL Server:
- `graph_nodes`: `id`، `type`، `name`، `description`، `since_year`، `complaints_12m`، `compliance_pct`، `net_sentiment`.
- `graph_edges`: `from_id`، `to_id`، `relation`، `since_year`.

مثال لنقطة الوصول: `GET /api/projects/{id}/graph?law=L1&year=2026`. يرجع JSON بنفس هيكل `JEEM_POLICY_GRAPH`، وأسئلة «اسأل جيم» يحولها الذكاء الاصطناعي إلى قائمة معرفات عقد (`ids`) ونص إجابة.

## لوحة تفاعلية: سير عمل المشتريات ومدة الخدمة (`procurement-workflow.html`)
خريطة عملية (Process map) ثابتة الترتيب بدل الشبكة الحرة، لأن سير العمل له اتجاه.
- **المراحل:** 9 مراحل، لكل منها مدة خدمة (SLA):
  - الاستلام (1)
  - المراجعة (3)
  - الدراسة الفنية (14)
  - الاعتماد المالي (5)
  - الطرح (21)
  - التقييم والترسية (10)
  - أمر الشراء (3)
  - التوريد (30)
  - الإغلاق (5)
- **المسارات الإضافية:**
  - مسارات الإعادة: إعادة للعميل، ومواصفات ناقصة، وإعادة طرح.
  - مسار الشراء المباشر المختصر.
  - مسارات الرفض والإلغاء.
- **العملاء:** مدخل الخريطة يمينًا. لكل عميل عدد طلباته المفتوحة والمتجاوزة، والطلبات القادمة تنطلق منه إلى «استلام الطلب».
- **الموردون:** أسفل الخريطة، مرتبطون بمرحلة التوريد، ولكل مورد نسبة الالتزام بمدة التوريد. ولون بطاقة المورد حالة: أقل من 60% أحمر، ومن 60% إلى أقل من 80% برتقالي.
- **الطلب = نقطة داخل بطاقة مرحلته:** اللون **والشكل** حسب نسبة الأيام المستهلكة من مدة المرحلة:
  - دائرة خضراء: ضمن المدة، أقل من 80%.
  - مربع برتقالي: معرض للتأخر، من 80% إلى أقل من 100%.
  - معيّن أحمر: متجاوز للمدة.

  ألوان الحالة محجوزة ولا تُستخدم للسلاسل، ومعها أيقونة دائمًا.
- **بطاقة المرحلة:** تعرض عدد الطلبات قيد التنفيذ، والمدة مقابل المتوسط الفعلي، ومؤشرًا رصاصيًا (الخط = المدة المستهدفة).
- **سُمك كل انتقال = عدد الطلبات التي عبرته**، وعليه جسيمات متحركة تعطي إحساس التدفق، وتتوقف مع إعداد تقليل الحركة.

**التفاعل**
- **ضغطة على مرحلة:** إحصاءاتها (المتوسط، وأطول 10%، ونسبة التجاوز)، وأسباب التأخير الشائعة، وطلباتها مرتبة بنسبة التجاوز.
- **ضغطة على طلب:** يتنوّر مساره كاملًا على الخريطة بما فيه الإعادات، وتظهر رحلته مرحلة بمرحلة بالأيام مقابل المدة.
- **ضغطة على عميل أو مورد:** طلباته وأداؤه.
- **ضغطة على انتقال:** الطلبات التي سلكته.
- **الفلاتر:** أزرار العملاء أعلى الصفحة، وتصفية حسب حالة الالتزام.
- **البحث:** برقم الطلب أو اسمه أو اسم المورد.
- **الشريط الزمني:** يومي من 1 يناير إلى 30 سبتمبر، وزر التشغيل يحرّك النقاط بين المراحل.
- **«اسأل جيم»:** 6 أسئلة محسوبة من البيانات الفعلية: عنق الزجاجة، والمتجاوزة الآن، والإعادات، وأقدم طلب، والموردون المتأخرون، والعملاء الأكثر تأثرًا. وعند تحديد طلب يجيب عن «لماذا تأخر؟».
- **الرسوم أسفل الخريطة كلها أرقام فعلية:**
  - مؤشر رصاصي لكل مرحلة: نوع عنصر جديد `bullet` في `dash-render.js`.
  - التزام الموردين.
  - المتجاوزة حسب العميل.
  - جدول المتجاوزة الآن.

  وأصبحت الأشرطة الأفقية `hbars` تقبل قيمًا فعلية عبر `vals`.

**الملفات**
- `workflow-data.js`: المراحل وإحداثياتها، والانتقالات، والعملاء، والموردون، و88 طلبًا لكل منها زياراته للمراحل بالأيام.
- `workflow-graph.js`: المنطق كاملًا.
- قسم `.wf-*` في `app.css`.

**الربط مع الخادم**
يكفي سجل أحداث (Event log) لكل طلب: `request_id`، `stage`، `entered_at`، `left_at`، مع `client_id` و`supplier_id`. ومدة كل مرحلة من جدول إعدادات (`stage_sla`). منه تُحسب الزيارات والإعادات والحالة في أي يوم.

## لوحة تفاعلية: منصة المشتريات: العملاء والموردون (`procurement-marketplace.html`)
مخطط تدفق (Sankey) يُقرأ من اليمين لليسار: **العملاء (يطلبون) ← أنواع الطلبات ← المنصة (تجمع وتطرح) ← الموردون (يلبّون)**.
- **الأشرطة والألوان:**
  - عرض كل شريط = عدد الطلبات.
  - لون الشريط = نوع الطلب، بلون ثابت لكل نوع ومرتبة مُتحقق منها لعمى الألوان.
  - بطاقة كل عميل أو نوع أو مورد تعرض العدد وشريط الحالات.
- **حالة الطلب تُحسب في أي يوم:**
  - بانتظار العروض: قبل الترسية.
  - قيد التنفيذ.
  - متأخر: تجاوز المدة.
  - مكتمل.
  - ملغى: قبل الترسية.

  الطلبات غير المرساة تبقى **داخل المنصة** في بطاقتي «بانتظار العروض» و«ملغى»، فتظهر وظيفة المنصة كوسيط.
- **رأس المنصة:** نسبة الترسية، ومتوسط الأيام حتى الترسية، وعدد علاقات عميل ↔ مورد.

**التفاعل**
- **ضغطة على عميل أو نوع أو مورد أو أي شريط:** يتنوّر الجزء الخاص به داخل كل شريط عبر الأعمدة الثلاثة، فيظهر مثلًا أي موردين لبّوا طلبات عميل معيّن ومن أي أنواع.
- **ما يتحدث مع الضغطة:** المؤشرات، واللوحة (حالة الطلبات، والأطراف المقابلة مرتبة، والطلبات المتأخرة أولًا)، والرسوم.
- **التصفية حسب الحالة:** تعيد رسم الأشرطة بحركة ناعمة.
- **الشريط الزمني اليومي:** يعرض نمو العلاقات وتغيّر الحالات.
- **البحث وعرض الجدول.**
- **«اسأل جيم»:** أين تتركز المتأخرة؟ أي الموردين يخدمون أكثر العملاء؟ ما الطلبات بانتظار العروض؟ ما أكبر علاقة عميل ↔ مورد؟
- **الرسوم أسفل المخطط (أرقام فعلية):**
  - مصفوفة العملاء × الموردين: أصبح `heat` في `dash-render.js` يقبل `vals`.
  - زمن التنفيذ مقابل المدة لكل نوع: `bullet`.
  - نسبة التأخير لدى كل مورد.

**الملفات**
- `marketplace-data.js`: 6 عملاء، و5 أنواع، و8 موردين، و190 طلبًا.
- `marketplace-graph.js`: المنطق كاملًا.
- قسم `.mk-*` في `app.css`.

**الربط مع الخادم**

جدول طلبات واحد يكفي، وفيه الحقول التالية:
- `client_id`
- `request_type`
- `supplier_id`: فارغ قبل الترسية.
- `created_at`
- `awarded_at`
- `due_days`
- `completed_at`
- `cancelled_at`

ومنه تُبنى الأعمدة والأشرطة والحالات.

## لوحة تفاعلية: شبكة العملاء والموردين (`client-supplier-network.html`)
نفس محرك الشبكة (`network-graph.js`) بملف بيانات جديد هو `client-supplier-graph-data.js`. الملف **يُبنى من بيانات منصة المشتريات نفسها** (`marketplace-data.js`)، فتتطابق الأرقام بين اللوحتين.
- **مواضع العقد:** العملاء مثبتون على قوس يمين الشبكة، والموردون على قوس يسارها، والمنصة في المركز.
- **المشاريع:** بينهم 43 **مشروعًا** (مربعات)، وكل مشروع هو علاقة عميل بمورد. يُسمّى المشروع حسب نوع الطلبات الغالب فيه والعميل، مثل «مشروع التحول الرقمي · الجامعة». حجم المربع حسب عدد الطلبات المرساة، وفيه حالاتها وقيمتها والتزامها بالمواعيد. في الربط الحقيقي يُستبدل الاسم المولَّد باسم المشروع أو العقد الفعلي من جدول `projects` (`client_id`, `supplier_id`, `name`).
- **أنواع الطلبات (سداسيات):** متصلة بالمنصة وبالعلاقات التي تضمها.
- **التأخيرات (معيّنات):** تظهر عند الموردين الذين لديهم طلبات متأخرة الآن، ومتصلة بالعلاقات المتأثرة.
- **تحديد عميل:** تتنوّر مشاريعه **والموردون المنفّذون** معًا، وتتحدث المؤشرات ومصفوفة العملاء × الموردين وجدول أكبر المشاريع على نطاقه. ونفس الشيء عند تحديد مورد.
- **«اسأل جيم»:** 4 أسئلة محسوبة من البيانات:
  - من يخدم أكبر عدد من العملاء؟
  - أين تتركز المتأخرة؟
  - ما أكبر مشروع؟
  - أي العملاء يعتمدون على مورد واحد (تركّز يستحق التنويع)؟

**إضافات للمحرك**
- `cfg.anchorFor(n)`: تثبيت أي نوع على موقع.
- `cfg.focus(n)` و`cfg.focusEdge`: نطاق التنوير أبعد من الجيران المباشرين.
- `types.major`: اسم العقدة ظاهر دائمًا.

## لوحة تفاعلية: مراقبة شبكة المنشأة أثناء الفعاليات (`venue-ops.html`)
نموذج مستوحى من تصميم لوحات مراقبة البنية التحتية بالوضع الداكن، أُعيد بالكامل بمحتوى عام وبلا أي علامات تجارية. الوضع الداكن محصور داخل اللوحة (`.vo`) ومتغيراته محلية، فلا يؤثر على بقية التطبيق.

**المحتوى**
- **شجرة البنية التحتية:** 3 نقاط رئيسية يمينًا (حساس المدخل، نقطة الوصول الرئيسية، وحدة التحكم الرئيسية) تتفرع إلى 12 جهازًا في 4 صفوف.
  - **الوصلات:** متعامدة، و**نبضات مضيئة** تتحرك عليها بسرعة تتناسب مع معدل النقل، وتصبح حمراء للأجهزة الحرجة.
  - **بطاقة كل جهاز:** حلقة الصحة، وعدد المتصلين، وشارة التنبيهات. لون البطاقة حسب الحالة: يعمل، أو تحذير، أو حرج بخلفية مخططة.
- **الشريط العلوي:** الحضور، والأجهزة المتصلة، والتنبيهات النشطة، ومستوى الكمون بخمس درجات.
- **اللوحة الجانبية:** مؤشرات الشبكة الرئيسية، واستهلاك الشبكة لكل فعالية (حلقات + أعمدة مزدوجة: الذروة والمتوسط).
- **جدول «تفصيل البنية التحتية»:** صفوف قابلة للطي لكل نقطة رئيسية وأجهزتها، بالحالة ومعدل النقل والمتصلين.

**التفاعل**
- **بث مباشر:** القيم تتحدث كل ثانيتين، مع زر «مباشر/متوقف».
- **ضغطة على جهاز:** يتنوّر مساره من النقطة الرئيسية ويبهت الباقي، وتعرض اللوحة الجانبية:
  - الصحة، والمتصلين، ومعدل النقل، والكمون.
  - منحنى حركة البيانات الحية.
  - الأجهزة المتفرعة.
  - التنبيهات.
  - أزرار: إعادة تشغيل، عزل، اسأل جيم.
- **تبديل البوابة:** أ أو ب أو ج، ولكل بوابة بياناتها.
- **التكبير والسحب:** تكبير وتصغير وملاءمة وسحب للتحريك.
- **«اسأل جيم»:** الأجهزة الحرجة، والضغط الأعلى، وجاهزية البوابات للذروة، أو سؤال عن الجهاز المحدد. تتنوّر الأجهزة المعنية مع الإجابة.

**الربط مع الخادم**
- `devices`: `id`، `name`، `kind`، `parent_id`، `x`، `y` (مواضع الرسم).

## صفحة المشروع: المحلل الذكي (`project-analyst.html`)
صفحة جديدة داخل المشروع، تحت «المحادثة واللوحات» في القائمة الجانبية وتبويبات المشروع (`PROJECT_SUB` و`proj_tabs`). مخصصة للأسئلة التحليلية فقط، ومنفصلة عن لوحات المتابعة: لا تُنشئ لوحات ولا عناصر.

**التخطيط**
- مساحة التحليل يمينًا والمحادثة يسارًا، مثل صفحة المحادثة واللوحات.
- كل عمود يمرّر داخليًا، وصندوق الكتابة ثابت أسفل المحادثة.

**المحادثة**
- **مراحل ظاهرة لكل سؤال أثناء التنفيذ:** فهم السؤال ← اختيار المصادر ← كتابة الاستعلام ← التحقق من الأرقام ← صياغة الإجابة. بعد الانتهاء تُطوى في سطر «تمّ في X ثوانٍ · N مصادر».
- **حالة توثيق لكل إجابة:**
  - علامة صح = **موثّقة**: طابقت إجماليات المصدر.
  - «!» = **غير موثّقة**: مثلًا مصدر لم يُحدَّث منذ 3 أيام.
- **أسماء الكيانات في الإجابة روابط:** تفتح النتيجة وتُبرز الصف في الجدول.
- **«عرض في مساحة التحليل»** على كل إجابة. الإجابة المعروضة حاليًا مظلّلة.
- **أسفل المحادثة:**
  - أسئلة مقترحة (+N).
  - إدخال صوتي.
  - زر اختيار المصادر.
  - شرائح المصادر المرفقة بالسؤال، قابلة للإزالة، ومعلَّم القديم منها.

**مساحة التحليل**
- **العنوان والتوثيق:** العنوان، ونوع النتيجة، وحالة التوثيق.
- **التحذير والتحقق:** تحذير بالسبب، وزر **«تحقق الآن»** (مزامنة المصدر ثم مطابقة الأرقام، فتتحول الإجابة إلى موثّقة في المحادثة والمساحة معًا).
- **«مصادر البيانات»:** الجداول المستخدمة، وحداثة كل مصدر، و**الاستعلام SQL** الفعلي.
- **«الوصف المختصر» (قابل للطي):**
  - ملخص نصي.
  - بحث في النتائج.
  - تنزيل CSV.
  - تبديل جدول/رسم.
  - جدول قابل للفرز.
- **«التحليل» بثلاثة أزرار جاهزة:**
  - **لخّص:** الأعلى، والأدنى، والتركّز، وتوصية.
  - **اشرح أهم المقارنات:** أفضل 3 مع وصف، ورسم مقارنة بخمسة مقاييس (0–100) يتبدّل بين البنود.
  - **صِف الأفضل.**
- **إجراءات:** حفظ كتقرير (في «الملفات»)، ومشاركة النتيجة (لمن لديه صلاحية على المشروع)، وسؤال متابعة.

**البيانات والسيناريوهات**
- 5 سيناريوهات تجريبية: المنتجات، والأجهزة الأعلى نموًا، والمناديب، والمناطق، والعملاء.
- السؤال الحر يُوجَّه بالكلمات المفتاحية. وما لا يمكن الإجابة عنه من المصادر يُعتذر عنه صراحة بدل التخمين.
- **في الإنتاج يرجع الخادم لكل سؤال:**
  - `{ title, summary, columns, rows, sql, sources, verified, why, comparison }`
  - التوثيق = مطابقة إجمالي الاستعلام مع إجمالي مرجعي من المصدر، مع فحص حداثة المزامنة.

الملف `assets/js/analyst.js`، وقسم `.an-*` في `app.css`.

> **إصلاح عام:** أصبحت الخلايا الرقمية في كل الجداول المولّدة `<td><span class="num">` بدل `<td class="num">`، لأن `.num { display: inline-block }` كان يكسر محاذاة أعمدة الجداول.

## شاشة المشروع: اللوحات المنشورة — `project-published.html`

شاشة جديدة تحت المشروع (في القائمة الجانبية وشريط أقسام المشروع بعد «المحادثة واللوحات») تعرض **كل لوحات المتابعة المنشورة على المشروع** كتبويبات متجاورة.

**مستويان من التبويبات بتمييز بصري واضح:**
1. **تبويبات اللوحات (المستوى الأول):** بنمط «تبويب ملف» ملتصق بإطار اللوحة، مع خط علوي بلون الهوية للتبويب النشط. كل تبويب يعرض نقطة الحالة (أخضر ممتلئ = بيانات حية، حلقة برتقالية = تحديث مجدول) + الاسم + عدد صفحات اللوحة إن كانت أكثر من صفحة + وسم «تفاعلية» للوحات التفاعلية.
2. **تبويبات صفحات اللوحة نفسها (المستوى الثاني):** داخل إطار اللوحة، بنمط خط سفلي أصغر مسبوق بعنوان «صفحات اللوحة» — ترسمها `JR.mount` من `d.p` كما هي، وتختفي تلقائيًا للوحة ذات الصفحة الواحدة.

**السلوك:**
- **تحميل كسول:** اللوحة تُركّب عند أول فتح لتبويبها فقط، و**تحتفظ بصفحتها الداخلية وفلاترها** عند التنقل بين اللوحات والعودة.
- **رابط عميق:** `#d=<معرّف اللوحة>&p=<رقم الصفحة>` يتحدث مع كل تنقل، و«نسخ رابط هذه الصفحة» ينسخه — من يفتح الرابط يصل لنفس اللوحة ونفس الصفحة الداخلية.
- **كثرة اللوحات:** التبويبات تتمرر أفقيًا بتلاشي على الحافة وأسهم تظهر فقط عند الحاجة، وزر «كل اللوحات (N)» يفتح قائمة ببحث بالاسم أو الجمهور. على الجوال تنتقل الأزرار لسطر فوق التبويبات وتُسحب التبويبات باللمس.
- **الترتيب:** المالك والمحرر يعيدون ترتيب التبويبات بالسحب أو بـ Ctrl + سهم (المشاهد لا). الترتيب في النموذج يُحفظ في المتصفح؛ في الإنتاج حقل `sort_order` على مستوى المشروع.
- **لوحة المفاتيح (نمط tablist):** ← → للتنقل (في RTL: اليسار = التالي)، Home/End، والتبويب النشط فقط في ترتيب Tab.
- **شريط معلومات كل لوحة:** الناشر، التاريخ، رقم الإصدار، الجمهور، نوع التحديث وتكراره، عدد الصفحات + «نسخ الرابط» و«تصدير PDF» و«تعديل في المحادثة واللوحات» (للمالك/المحرر فقط).
- **وضع العرض:** ملء الشاشة ويمر تلقائيًا كل 12 ثانية على **صفحات اللوحة الحالية ثم ينتقل للوحة التالية**، بشريط تقدم أعلى، ويتوقف مؤقتًا عند مرور الفأرة، و`Esc` للخروج.
- **نوعان من اللوحات:** لوحات JR المبنية من المحادثة تُركّب مباشرة، واللوحات التفاعلية تُضمّن بإطار `iframe` بالرابط `?embed=1` — وضع التضمين في `app.js` يخفي القائمة والشريط العلوي ويرسل ارتفاع المحتوى للصفحة الأم عبر `postMessage({ jeemEmbedH })`.

**عقد البيانات المقترح:** `published_dashboards(id, project_id, dashboard_id, version, published_by, published_at, audience, refresh_mode: live|scheduled, refresh_every, sort_order, kind: jr|interactive, embed_url?)` + صفحات اللوحة من تعريفها (`d.p`). يُعرض للمستخدم فقط ما يسمح به جمهور النشر ودوره في المشروع.

**المرجع:** `project-published.js`، قسم `.pd-*` و`.is-embed` في `app.css`.



## نموذج لوحة: متتبع الفرص والعروض

نموذج جاهز في مكتبة اللوحات (`pl-opportunities-tracker`، فئة المبيعات، 3 صفحات) مأخوذ من لوحة Power BI لمتابعة الفرص، ومُعمَّم ليصلح لأي جهة:
- **الملخص:** العروض المقدّمة والمكسوبة (قيمة + عدد)، المستهدف السنوي بنسبة التحقيق، استغلال الاتفاقيات الإطارية؛ قيمة المقدّم حسب الجهة المالكة؛ القيمة حسب القطاع (متأخرة/مقدّمة/مكسوبة)؛ عام أم خاص؛ العدد حسب ربع التقديم؛ العدد حسب مدير الحساب.
- **مراحل الفرص:** عنصر `stages` بالمراحل الأربع (التأهيل ← إعداد الاستجابة ← التقديم ← التعاقد) مع الحالات الفرعية (ملغاة، غير مؤهلة، معلّقة، خاسرة، متأخرة)؛ حسب خط الأعمال؛ حسب النوع (RFP / اتفاقية إطارية / RFQ)؛ حسب ربع التقديم؛ حسب العميل.
- **التفاصيل:** المكسوب (عدد + قيمة)؛ القيمة والعدد حسب مدير الحساب؛ حسب خط الأعمال والعميل؛ **سجل الفرص** (مدير الحساب، الرقم المرجعي، الاسم، الجهة المالكة، القيمة بدون الضريبة، قناة التقديم، التاريخ، القطاع، المرحلة).
- **الفلاتر:** السنة، مدير الحساب (بديل قائمة الاختيار الجانبية في الأصل)، الجهة المالكة، نوع الفرصة.

**النوع الجديد `stages`** (مسار عملية متعدد المراحل، قابل لأي عملية: مشتريات، توظيف، معاملات):
`{ t: 'stages', st: [{ n: 'التأهيل', tot: 165, it: [['كل الفرص', 165, 'info'], ...], sub: [['ملغاة', 8, 'dark'], ...] }] }`
- كل خانة: `[التسمية، العدد، النبرة، القيمة؟]` والنبرة `info|ok|warn|bad|dark|mute` — اللون دائمًا مع نص التسمية.
- الأسهم بين المراحل باتجاه القراءة RTL، وعلى الجوال تتكدس المراحل عموديًا.
- مع تغيير الفلاتر تتحرك كل القيم بنسبة واحدة لتبقى المجاميع متسقة.
- إضافة صغيرة: الأعمدة المفردة (`bars`) تقبل الآن `vals` بقيم فعلية مثل `hbars`.

**عقد البيانات المقترح:** `opportunities(id, ref_no, name, client, account_manager, owner_unit, business_line, type, sector, is_public, submission_channel, submitted_at, value_wo_vat, stage, sub_status)` + `targets(year, value)` + `framework_agreements(cap, used)`.
