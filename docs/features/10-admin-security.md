# 10. الإدارة والأمان

## 10.1 المنظمات والمشاريع والأدوار

- **مالك المنصة** ينشئ المنظمات ويعلّقها ويعيّن مسؤوليها، ويملك مكتبة النماذج والقواعد العامة.
- **المنظمة** لها مسؤولون ومستخدمون، ومشاريع متعددة؛ لكل مشروع مخططه المعزول وملفاته ولوحاته
  وعروضه وتصاميمه وهويته.
- **أدوار المشروع**: مالك، محرر، مشاهد؛ تتحكم في الرؤية والتعديل والنشر وجمهور اللوحات
  المنشورة. الحساب بلا دور صريح يُعامل كمشاهد.
- **صلاحيات المصادر لكل مستخدم**: أنظمة وتصنيفات وملفات بعينها؛ وتسري في طبقة الاستعلام.
- الدخول بحساب محلي بتجزئة كلمة مرور قياسية؛ ومفاتيح وصول شخصية للأتمتة.

## 10.2 مكتبة النماذج والقواعد

مالك المنصة يعدّل نماذج المحادثة ونماذج اللوحات ومكتبة المؤشرات (6 أنواع مقاييس وصفوفها) والقواعد
العامة التي يراها الموديل، بتعديلات متناثرة فوق الأصل مع الرجوع إلى الأصل في أي وقت؛ ويخفي أو
يضيف نماذج. التعديل يظهر فورًا في معرض كل المنظمات وفي تصميم حر.

## 10.3 الأمان (ملخص ما ورد في الفصول)

| الطبقة | الآلية |
|---|---|
| البيانات | مخطط لكل مشروع؛ المدقّق يرفض أي جدول خارج المسموح؛ قراءة فقط؛ صلاحيات لكل ملف ومستخدم |
| الموديل | يرى تعريف البيانات ونتائج استعلامات محكومة فقط؛ موديل محلي ممكن بلا مزوّد خارجي |
| المفاتيح | مفاتيح المزوّدين مشفّرة في القاعدة ولا تُعاد ولا تُكتب في ملفات؛ مفاتيح الوصول مجزَّأة |
| الصفحات المنشورة | إطار معزول بأصل معتم + سياسة أمن محتوى؛ جسر رسائل محدود العقد |
| البيانات الحيّة | تُنفَّذ بصلاحيات صاحب التصميم؛ لا SQL في مسار المشاهد |
| المساعد | ملزَم بمحتوى الصفحة؛ سقف أسئلة؛ المحادثة لا تُخزَّن على الخادم |
| التدقيق | كل نداء موديل بنصه الكامل وأدواته وتكلفته وصاحبه |

## 10.4 التشغيل والنشر

- تطبيق ASP.NET Core واحد يخدم الواجهة والـ API من عنوان واحد؛ الواجهة HTML/CSS/JS بلا خطوة بناء
  وكل مكتباتها محلية (تعمل بلا إنترنت).
- SQL Server محلي أو Express أو Azure SQL؛ ترحيل المخطط تلقائي عند الإقلاع.
- Docker Compose للنشر الذاتي، وخط نشر على Azure DevOps.
- واجهة ثنائية اللغة (عربي/إنجليزي)، جولة تعريفية للمستخدم الجديد، تصميم متجاوب حتى 390px مع
  احترام تقليل الحركة.
- وضع ليلي حقيقي يختاره كل مستخدم من قائمة «إعداداتي» ويُحفظ في متصفحه: أسطح ونصوص وحدود داكنة، ألوان هوية وحالات
  مفتّحة للتباين، والرسوم البيانية تتبعه تلقائيًا. الافتراضي فاتح.

## صلاحيات الشاشات لكل مستخدم

- يحدد المسؤول لكل مستخدم عادي الشاشات التي يراها، أو «كل الشاشات». اختيار جاهز «تصميم حر فقط» يعطيه تصميم حر وشاشة الملفات (ليرفع بياناته)
  ويوقف الأنظمة الخارجية المشتركة، فيدخل ليجد تصميم حر وبياناته هو فقط.
- الإخفاء ليس شكليًا: الخادم يرفض واجهات الشاشات غير المسموحة، مع إبقاء ما تحتاجه الشاشات المسموحة نفسها.



## الكيانات وأنواعها: مشروع، قسم، إدارة، فريق…

**ما هي**: الكيان هو ما تُنظَّم تحته مساحة العمل (المحادثة، اللوحات، التصاميم، الملفات، الصلاحيات). كل منظمة تسمّيه كما تسمّيه هي، ويمكن أن تجمع أكثر
من نوع (أقسام وإدارات ومشاريع معًا).

**كيف تعمل**: مسؤول المنظمة يعرّف الأنواع (الاسم مفردًا وجمعًا، مذكرًا أو مؤنثًا، وأيقونة، ونوع افتراضي) ويختار نوع كل كيان. المنصة كلها تتكلّم بلغة النوع
الذي يعمل فيه المستخدم: «الإدارة الحالية»، «بيانات قسمك»، «أعضاء الفريق»؛ وشاشة الكيانات تجمعها بحسب النوع.

**التبديل بين الكيانات**: زر «تبديل» بجوار الكيان الحالي في القائمة الجانبية (أو النقر على كارت الكيان) ينقل المستخدم إلى مساحة عمل كيان آخر له فيه دور؛ الاختيار محفوظ له ويلتزم به كل شيء (المحادثة واللوحات والتصاميم والملفات والمصادر)، وكل كيان يبدأ ببياناته الخاصة.

**القيود الحالية**: لكل نوع اسم إنجليزي اختياري يظهر في الواجهة الإنجليزية (Department، Directorate…)، لكن ترجمة الواجهة الإنجليزية نفسها ما زالت جزئية في كثير من الشاشات. (داخليًا صار الاسم «Entity» في الكود وقاعدة البيانات، بترحيل تلقائي عند أول تشغيل.)
